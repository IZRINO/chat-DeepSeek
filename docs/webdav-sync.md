# WebDAV 会话同步设计与验收

用户在电脑上聊完一轮，打开手机就能看到同一个会话、切换到先前的回答分支、打开原来的 PDF，并从那里继续聊。网页版、Windows 和 Android 连接同一个同步目录。远端保存完整会话历史，首次合并两端数据，日常传输以有变化的会话和附件为单位。[项目术语](../GLOSSARY.md) · [目录格式的选择依据](adr/0001-webdav-sync-directory.md)

## 同步什么

| 对象 | 换设备后的行为 |
| --- | --- |
| 会话 | 保留稳定 ID、标题、时间、整棵消息树及继续对话所需的状态。正文、思考、引用、搜索结果、模型、用量、回复状态和已选分支都能恢复。 |
| 附件 | 同步本机能取得的图片、PDF 和其他文件原件。重复引用同一原件只上传一次。历史记录缺少原件时保留文件信息，并标为「原件缺失」。 |
| 本机数据 | 草稿、当前打开哪个会话、界面设置、聊天和搜索 Key、WebDAV 凭据留在本机。接收端用自己的聊天服务和凭据发送消息，需要时用原件重新上传附件。 |

同步文件可以在网盘里直接阅读。有读取权限的人能看到消息和原件，包括用户自己写进消息的敏感信息。公网连接使用 HTTPS 保护传输。现有 ZIP 仍可用于手动导入导出。它只携带图片原件，还会省略部分续聊状态。[本地消息模型](../src/services/chat/types.ts) · [现有归档范围](../src/services/chat/history/README.md#导出范围)

## 什么时候同步，用户看到什么

- 回复完成、用户停止、请求失败，都以本机最后保存的一问一答为准。会话和待同步标记一起落盘，同步在后台运行。流式文字只更新本机，一轮中的多次保存合并为一次待办。中途退出时，下次打开将中断的回复按已停止状态补同步。
- 打开应用、回到前台、恢复联网或点「立即同步」时，先检查远端更新。重命名、删除和重新生成也会触发同步。有回答正在生成的会话，在本轮落盘后再应用远端变化。收发失败时仍能继续聊，已完成的项目下次可以复用。
- 聊天页与设置页共用一份进度。先显示「正在检查」，确定数量后显示「正在上传 报告.pdf · 已完成 3/8 项」或对应的下载状态。一次实际传输的会话或附件算一项。单个大文件传完后进度前进一步。提交目录和保存本机结果期间显示「正在保存」，两边完成才显示「已同步」。失败显示「待同步」及原因，可手动重试。

## 两台设备分别修改时

| 例子 | 用户看到的结果 |
| --- | --- |
| 电脑聊 A，手机聊 B | 两个会话都出现在两端，各一份。 |
| 两端从同一版 A 分别继续聊 | 先提交的版本沿用原会话，另一份以「原题（设备名 · 冲突副本）」出现在列表，两份都可以继续聊。重试、刷新或接入第三端后仍只有这两份。 |
| 电脑删除 A，手机没有新修改 | 手机下次同步也移除 A。目录保留删除标记，让长期离线的设备识别这次删除。 |
| 电脑删除 A，手机离线期间又在 A 里聊了一轮 | 原会话跟随删除，手机整段对话保留为「恢复副本」，同步到其他设备。 |
| 手机只是浏览或切换已有分支 | 新设备首次打开采用随会话保存的分支。此后切换分支属于本机阅读位置，接着提问时才随新会话版本保存。已打开的会话保留设备当前的阅读位置。 |

冲突判断以两端共同同步过的版本为准。手机时钟快五分钟不会改变哪一份被保留。首次连接出现相同 ID、不同内容且没有共同版本依据时，也保留两份。[冲突与删除决策](adr/0002-webdav-conflict-copies.md)

## 清空历史和导入 ZIP

两个入口默认作用于本机。开始本机清空或导入前暂停同步并等待在途写入结束，成功后保持断开，由用户决定何时重新合并。已启用同步的用户也可以明确选择「替换所有设备的历史」，确认页显示同步目录、受影响的会话数和清空或替换后的数量。

全端替换先校验导入文件和原件，再一起发布新索引和代次。确认后若有其他设备刚提交新内容，重新展示影响范围再执行。无网时保留本机操作入口，全端替换需要能核对远端状态。索引提交前中断，原先的远端历史仍然有效。若提交应答丢失，恢复连接后先按替换操作的标识核对结果。

其他设备下次上线先识别目录换代，作废旧上传队列，按新目录刷新。离线期间独有的修改在该设备留作待处理副本，用户可手动恢复。这样既能清空所有设备的共享历史，也能防止旧手机自动把已经清空的记录传回来。[现有本机替换入口](../src/services/chat/backup.ts)

## 建议的目录与提交方式

下图是应用专用子目录的示例。会话标题可以改，文件路径使用稳定标识。`index.json` 指向当前生效的文件，旧版本和中断的传输由应用回收。

```text
真DEEPSEEK/
  index.json                            格式版本、目录标识、代次、会话版本和删除标记
  sessions/<会话ID>/<版本ID>.json        可读的完整会话，含各分支及附件引用
  files/<内容指纹>-报告.pdf              原始文件，显示名称保存在会话中
```

1. 每台设备记录上次成功同步的目录、代次和会话版本。检查索引后分别列出需要上传和下载的项目。长会话有修改时，首版重传这一个会话的 JSON。索引按内容指纹登记原件路径，同一文件以不同名称被引用时，复用已登记的原件，各条消息保留自己的显示名称。
2. 先传原件和带新版本号的会话文件，再提交索引。首次创建索引用 `If-None-Match: *`，更新用服务器给出的强 `ETag` 做 `If-Match` 条件写入。发生 `412` 时重读索引、重新合并并复用已传文件。若服务端已经提交但客户端没收到应答，重读索引核对结果，避免重复制造副本。
3. 下载先校验会话格式、引用和原件指纹，再用本机事务提交会话、附件和同步进度。收到未知格式、损坏文件或已绑定的索引突然消失时，暂停并保留本地历史，待用户重新核对目录。清理只涉及应用创建、已无引用且没有进行中传输使用的对象，共用的原件保留。全端清空时区分「历史已清空」与「旧文件待清理」，网盘自身的回收站由服务商管理。
4. 在「设置 → 数据管理 → WebDAV 同步」填写服务地址、目录与独立凭据。初始化使用新的专用子目录，或接入能识别的已有目录。同名目录里已有其他文件时，保留这些文件并提示另选位置。连接测试只使用专用目录内属于本次测试的文件，核对建目录、读写、清理、强 `ETag` 与实际拒绝过期写入的行为。无法保证并发安全时说明不兼容。远端文件名和索引中的路径须限制在该目录内，凭据只发往配置的服务。

网页版从 GitHub Pages 直连，需要 HTTPS。服务端须允许来源 `https://izrino.github.io` 的预检和实际请求，包括目录操作 `PROPFIND`、`MKCOL`，文件操作 `GET`、`PUT`、`DELETE`，以及 `Authorization`、`Depth`、`Content-Type` 和条件写入所需的请求头。响应须向浏览器暴露 `ETag`。跨域失败时浏览器给脚本的信息有限，界面应提示检查网络与跨域配置。两个安装版走原生 HTTP，需要为用户配置的 WebDAV 目录补充访问能力。现有原生权限只列出了聊天相关路径。[原生权限](../src-tauri/capabilities/default.json) · [浏览器跨域](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CORS) · [跨域读取响应头](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Access-Control-Expose-Headers) · [条件更新](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/If-Match) · [条件创建](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/If-None-Match)

## 验收场景

| 操作 | 通过条件 |
| --- | --- |
| 首次把电脑已有的两个会话和目录里独有的第三个会话合并，再连接空手机 | 三端都得到三个会话。新手机能切换分支、复制正文、打开 PDF、继续提问。缺原件的旧记录仍可阅读。 |
| 只在一个会话聊一轮，再点一次「立即同步」 | 首次只上传变化的会话和新增原件。第二次没有变化，除索引检查外无需传输内容。 |
| 分别完成、停止、故意触发请求失败，生成中强退后重开 | 每次恢复已保存的终态和文本。连续流式输出不逐字发 WebDAV 请求。 |
| 上传大附件时断网、关闭应用，再重开联网 | 进度显示当前文件和真实项数，聊天仍可用。另一台设备只会读取上次完整提交的数据。重试后文件内容一致。 |
| 两端离线改同一会话，再同时上线；索引写入成功后让一端丢失应答 | 最终恰有两份会话，两个设备的新增内容都在。反复同步不会增加副本。 |
| 删除有共享附件的一个会话，再接入一台有离线修改的设备 | 未修改的设备跟随删除，另一会话的附件仍能打开，离线修改最终只形成一份恢复副本。 |
| 先只清空本机，再分别试验全端清空、有效 ZIP 全端替换和损坏 ZIP | 本机清空时远端完好。全端操作成功后各端共享同一份新历史，旧队列不会回灌。损坏 ZIP 和发布失败均保留旧远端历史。 |
| 在网页版和两套安装版测试同一 HTTPS WebDAV，再测试缺少跨域许可、错误凭据、条件写入失效 | 三端在兼容服务上得到一致结果。网页版能提示跨域排查方向，认证或并发保护失败时可纠正设置，本地对话仍可用。 |
